# USER HARD GATES
# Human-Only Enforcement Layer

This document defines the checks that ONLY the human owner
can validate correctly.

AI may assist, but may NOT self-certify these gates.

Authority:
AI_BUILD_CONSTITUTION.md > PROJECT_GENESIS_V2.md > HARD_GATES.md > USER_HARD_GATES.md

If any gate fails, the project is either:
- Paused
- Re-scoped
- Reframed
- Or explicitly accepted as a personal-only artifact

---

## HOW TO USE THIS FILE

This checklist must be run at THREE moments:

1. Before committing seriously (early reality check)
2. Before public exposure (pre-launch)
3. After first real-world feedback (post-contact audit)

AI input is allowed.
Final judgment is NOT delegable.

---

## TIER 1 — EXISTENCE JUSTIFICATION
(Answers: “Should this exist at all?”)

[ ] I can explain this project in one sentence without qualifiers
[ ] I can explain who this is for without saying “basically everyone”
[ ] I can explain why this exists *now* and not later
[ ] I can explain why this is not just personal novelty

# COMMENT:
# If this only exists because it feels interesting,
# that is acceptable ONLY for private projects.

---

## TIER 2 — UNFAIR ADVANTAGE (NON-NEGOTIABLE FOR PUBLIC PROJECTS)

[ ] I can clearly state the ONE dimension where this is unfairly better
[ ] That advantage is noticeable within minutes, not explanations
[ ] That advantage is not purely technical novelty
[ ] A competitor cannot trivially copy this without changing incentives

# COMMENT:
# “It’s cleaner,” “it’s faster,” or “it’s modern” are not unfair advantages.
# Reframing effort, time, or cognition usually is.

---

## TIER 3 — USER EMPATHY REALITY CHECK
(Answers: “Would anyone actually engage with this?”)

[ ] I am not projecting my own preferences onto users
[ ] I can articulate a real frustration this removes
[ ] I can explain why a user would care *before* understanding how it works
[ ] I can explain why someone would return to this a second time

# COMMENT:
# “I think it’s cool” is not evidence.
# Neither is “people should care.”

---

## TIER 4 — TIME & ATTENTION WORTHINESS
(Answers: “Is this worth stealing attention from better things?”)

[ ] This deserves time compared to existing alternatives
[ ] This earns attention without coercion or dark patterns
[ ] This does not rely on novelty alone to hold interest
[ ] This respects user intelligence and agency

# COMMENT:
# Attention is the most expensive currency.
# Borrow it carefully.

---

## TIER 5 — PERSONAL HONESTY CHECK
(Answers: “Am I lying to myself?”)

[ ] I am not continuing solely because I’ve already invested time
[ ] I am not avoiding killing this because it feels like failure
[ ] I would still build this if no one praised it
[ ] I am not inflating importance to justify effort

# COMMENT:
# Killing a project early is often a sign of clarity, not weakness.

---

## TIER 6 — QUALITY SELF-AUDIT
(Answers: “Is this actually as good as I think it is?”)

[ ] I would be impressed if someone else shipped this
[ ] I would trust this product if I didn’t build it
[ ] I would recommend this without caveats
[ ] I would be annoyed if this were worse

# COMMENT:
# Pride is not the metric.
# Respect is.

---

## TIER 7 — SCOPE & ENERGY ALIGNMENT
(Answers: “Is this the right project *for me*?”)

[ ] This aligns with my current goals
[ ] This is not a distraction from higher-leverage work
[ ] This fits my available time and attention
[ ] This does not require me to become someone else to finish

# COMMENT:
# Good ideas at the wrong time are still wrong.
